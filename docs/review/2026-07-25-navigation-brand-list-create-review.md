# 左ペインのブランド表示と新規リスト編集UX レビュー

対象: GitHub Issue #186

## チェックリスト確認

- 仕様: `docs/mvp-spec.md` と `docs/issues/075-navigation-brand-list-create.md` に記録した。
- 設計: 左ペインは対象選択に集中し、アプリ名と開閉操作は画面全体の主見出しへ集約する。表示切替は中央ペイン枠内へ入れる。
- 実装範囲: Presentation層の左ペイン表示と入力確定UIに限定する。
- トランザクション境界: 既存の `onCreateTaskList` Use Case境界を再利用し、新しいRepository境界やDB変更は追加しない。

## 指摘事項

- 重大な設計破綻はなし。
- 新規リストのフォーカスアウト保存は、他ビューへのクリックと同時に発火するため、作成後のビュー選択とクリック先の遷移が競合する可能性がある。
- 表示切替、件数、追加ボタンが同じヘッダー内に入るため、狭い幅では折り返し時の視認性確認が必要。

## 破綻シナリオ

- ユーザーが新規リスト名を入力した状態で別ビューをクリックし、リスト作成と画面遷移がほぼ同時に走る。
- ネットワークは使わないが、Tauriコマンドが失敗した場合に入力欄が残り続ける。

## スケール懸念

- リスト最大数は10件のため、今回のUI変更による描画スケール問題は小さい。
- 左ペインのリスト数が上限に達した時は既存の上限判定で入力UIを閉じる。

## セキュリティ懸念

- リスト名はユーザー入力だがHTMLとして描画しない。
- 入力はPresentationでtrimし、Application側の既存検証を最終防衛とする。
- 外部通信、秘密情報、OS権限の追加はない。

## テスト不足

- 実機でのスクリーンリーダー読み上げ確認は未実施。
- フォーカスアウト保存とクリック先遷移の競合は手動確認が必要。

## 判断

フォローアップ付き承認。UI変更はPresentation層に閉じ、既存Use Case境界を保てている。手動確認では、新規リスト作成時のフォーカスアウト保存、空白入力、Escapeキャンセル、左ペイン開閉、検索幅、右詳細ペイン表示時の高さ揃いを重点的に見る。
