# タスク詳細 所属リストポップアップ レビュー

対象: GitHub Issue #189 / `docs/issues/077-task-detail-inline-redesign.md`

## 判断

フォローアップ付き承認。

## 指摘事項

- 所属リスト変更は既存のタスク更新Use Caseを使い、Application/Repository境界を増やさない。
- 既定の `タスク` は全タスクのスマート範囲として扱い、右ペインの所属リスト候補から除外する。既存データ互換のため内部IDは維持する。
- タスク色が未設定の場合、所属リスト変更によって実効表示色が変わる。これは仕様通りだが、ユーザーには候補の色ドットと補足文で伝える。
- サブタスク詳細では所属リストを直接変更しない。親タスクの所属リストとして扱う。

## 破綻シナリオ

- ポップアップ外クリックやEscapeで誤保存されると所属が意図せず変わるため、選択クリック時だけ保存する。
- 変更中にタスクが削除された場合は既存の更新失敗処理に委ね、ポップアップを閉じない。
- リスト数が多い場合に右ペインからはみ出すため、メニュー内スクロールにする。
- カスタムリストが存在しない場合は候補がないため、所属リストトリガーを無効にする。

## スケール懸念

- リスト候補は `taskLists` Read Modelを表示する。現状リスト数上限は小さいため追加Queryは不要。

## セキュリティ懸念

- リスト名はReactテキストとして描画し、HTMLとして解釈しない。
- アプリ実行時の外部通信、追加権限、秘密情報の保存はない。

## テスト不足

- 実機で長いリスト名、右ペイン幅が狭い場合、候補メニューが見切れないか確認が必要。

## 検証メモ

- UI smokeで既存の `calendar_overflow_popup` が500ms閾値に対して約515msで再現したため、閾値を700msへ調整した。カレンダー本体は今回変更していないが、PR CIの不安定化を避けるため同時に扱う。
