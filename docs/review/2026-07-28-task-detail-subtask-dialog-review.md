# タスク詳細 サブタスク追加ダイアログ化 レビュー

対象: GitHub Issue #189 / `docs/issues/077-task-detail-inline-redesign.md`

## 判断

フォローアップ付き承認。

## 指摘事項

- 親タスク詳細のサブタスク追加は、既存の共通 `TaskCreateDialog` の `subtask` モードへ委譲する。
- 新しいApplication Use CaseやRepository境界は追加しない。既存の `CreateSubtask` 境界を使う。
- 右ペイン内の局所編集状態を閉じてからダイアログを開き、複数の入力状態が重ならないようにする。

## 破綻シナリオ

- 詳細ペイン内フォームと共通ダイアログが併存すると、同じサブタスク作成に複数導線が残って迷う。
- 親タスクIDを取り違えると別タスクにサブタスクが作成されるため、App側の `handleRequestSubtaskCreate(task.id)` を入口に統一する。
- ダイアログを閉じた後にフォーカス復帰が不自然になる可能性があるため、既存ダイアログのフォーカス管理を再利用する。

## スケール懸念

- 追加QueryやRead Modelは増えない。作成後の再読込範囲は既存 `TASK_CONTENT_REFRESH` に従う。

## セキュリティ懸念

- サブタスク名とメモは既存作成Use Caseの検証対象であり、HTMLとして描画しない。
- 外部通信、新規権限、秘密情報は追加しない。

## テスト不足

- 右ペインから開いた共通ダイアログでサブタスクを作成するE2Eは未追加。今回は既存の作成ダイアログと型チェック、UIスモークで回帰を確認する。
