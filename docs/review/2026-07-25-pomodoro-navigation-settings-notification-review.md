# ポモドーロ画面遷移・設定・完了通知 レビュー

対象: GitHub Issue #185

## チェックリスト確認

- 仕様: `docs/issues/076-pomodoro-navigation-settings-notification.md` と `docs/mvp-spec.md` に記録した。
- 設計: ポモドーロ設定は集中画面へ集約し、通知はDB更新後の副作用として扱う。
- トランザクション境界: `complete_pomodoro_work_phase_and_notify` は先にRepositoryで状態更新し、その後に通知設定確認と通知送信を行う。
- 外部通信: 追加しない。

## 指摘事項

- 通知失敗は現時点で画面へ表示しない。状態更新の安定性を優先した判断。
- 直前画面はPresentation stateで保持するため、将来ビュー削除や導線非表示が増えた場合は戻り先の正規化が必要。

## 破綻シナリオ

- ポモドーロ表示中に前画面が通常導線から外れ、戻った時に空表示になる。
- 通知OFFなのに作業完了通知が送られる。
- 通知送信失敗で手動完了コマンド自体が失敗扱いになる。

## スケール懸念

- 設定フォームは単一レコードを編集するだけで、データ量による影響は小さい。
- 通知送信は1操作につき最大1件で、再試行ループは追加しない。

## セキュリティ懸念

- 入力は分数と回数の数値だけで、PresentationとDomainの両方で範囲検証する。
- 通知本文にユーザーメモやタグは含めない。
- 外部通信、新しいOS権限、秘密情報は追加しない。

## テスト不足

- 実機でのOS通知表示確認は未実施。
- ボタンちらつきは自動テストでは判定できず、手動確認が必要。

## 判断

フォローアップ付き承認。DB更新と通知副作用の分離は保てている。手動確認では、アイコントグル、設定保存、作業完了通知、通知OFF時の無通知、ボタンちらつき、狭い幅の設定フォームを確認する。
