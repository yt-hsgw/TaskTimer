# 左ペインのブランド表示と新規リスト編集UXを整理する

GitHub Issue: #186

## 背景

画面全体の主見出しとして `TaskTimer` を表示しているため、左ペイン内で同じアプリ名と `ローカルタスク` を再表示すると情報密度が下がる。左ペインは、今日、お気に入り、リスト、設定という操作対象を素早く選ぶ場所として扱う。

新規リスト作成は、既存のリスト名編集や今後のインライン編集仕様と揃え、保存ボタンを押す操作ではなく、Enterまたはフォーカスアウトで確定する。

## 仕様

- 左ペイン内の可視テキストから `TaskTimer` と `ローカルタスク` を外す。
- 左ペインの開閉ボタンは、左ペインを開いている時も右端に配置する。
- 新規リスト作成は入力欄だけを表示する。
- Enterまたは編集領域外へのフォーカス移動で、trim後の名称を保存する。
- 空白または空白のみの場合はリストを作成せず、入力状態を閉じる。
- Escapeではリストを作成せず、入力状態を閉じる。
- スクリーンリーダー向けのナビゲーション文脈と入力欄ラベルは維持する。

## 設計理由

- アプリ名は画面全体の主見出しに集約し、左ペインでは作業対象の認知に集中させる。
- 保存ボタンを外すことで、リスト編集、かんばん状態編集、タスク詳細のインライン編集と同じ操作モデルに近づける。
- 空白をtrimして判定することで、見た目上空のリストが作成されることを防ぐ。

## トレードオフ

- フォーカスアウト保存はクリック先の操作と同時に発火するため、意図せずリストが作成される可能性がある。
- 一方で、保存ボタンを残す案はUIの操作密度が上がり、既存のインライン編集方針と揃わないため採用しない。

## 代替案

- 新規リスト作成だけ保存ボタンを残す。
  - 明示性は高いが、左ペインの小さい入力UIでは操作数と視覚ノイズが増える。

## 危険ケース

- フォーカスアウト保存が、リストメニューや画面切り替えのクリックと競合する。
- 空白判定がtrimされず、空名リストが作成される。
- 見出しを削りすぎて、左ペインが何の領域かスクリーンリーダーで分かりにくくなる。

## 受け入れ条件

- 新規リスト名を入力して他の場所をクリックすると保存される。
- 空白または空白のみの入力ではリストが作成されない。
- 左ペイン内の `TaskTimer` と `ローカルタスク` の可視表示がなくなる。
- キーボード操作とスクリーンリーダー向けラベルが維持される。
