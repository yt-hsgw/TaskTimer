# ポモドーロの画面遷移、設定、完了通知を改善する

GitHub Issue: #185

## 背景

ポモドーロは独立機能として実装済みだが、画面遷移、設定導線、完了通知が日常運用に対してまだ分散している。集中機能の設定は設定画面ではなくポモドーロ画面で完結させ、画面右上の導線は表示中に戻れるトグルとして扱う。

## 仕様

- 画面上部のポモドーロアイコンを押すとポモドーロ画面へ移動する。
- ポモドーロ表示中に同じアイコンを押すと、直前の画面へ戻る。
- ポモドーロ画面内で以下を編集できる。
  - 作業時間。
  - 短い休憩。
  - 長い休憩。
  - 長い休憩までの作業回数。
  - 作業後の休憩自動開始。
  - 休憩後の次作業自動開始。
- 設定画面からポモドーロ設定セクションを外す。
- 作業フェーズを手動完了した時、DB更新後に既存ローカル通知adapterで完了通知を送る。
- 通知全体OFFの場合、ポモドーロ完了通知は送らない。
- 通知送信に失敗しても、ポモドーロ状態更新は成功扱いのままにする。

## 設計理由

- ポモドーロ設定を集中画面へ移すことで、設定変更と開始操作の距離を短くする。
- アイコンをトグルにすることで、ポモドーロ確認後に元の作業へ戻りやすくする。
- 通知はDBコミット後の副作用とし、状態変更のトランザクション境界へ混ぜない。

## トレードオフ

- 設定画面からポモドーロ設定が消えるため、すべての設定を1画面で探したい利用者には一手間増える。
- 通知失敗をUIへ返さないため、完了通知が出なかった理由はこの操作だけでは見えない。

## 代替案

- 設定画面とポモドーロ画面の両方に設定フォームを置く。
  - 発見性は上がるが、同じ設定UIが二重化し、どちらが正か分かりづらくなるため採用しない。

## 危険ケース

- 直前画面が削除済みまたは通常導線から非表示の画面で、戻り先が破綻する。
- 設定変更中にアクティブポモドーロの残り時間へ即時反映されると、現在セッションの意味が変わる。
- 通知OFF設定中にも完了通知が送られる。
- 通知失敗でポモドーロ状態更新までエラー扱いになる。

## 受け入れ条件

- ポモドーロアイコンでポモドーロ画面と直前画面を往復できる。
- ポモドーロ時間設定と自動開始設定がポモドーロ画面内で保存できる。
- ポモドーロの主要操作、補助操作のボタンは操作中もレイアウトと見た目がちらつかない。
- 補助操作と下部設定エリアの区切り線は十分な余白を保つ。
- 設定画面にポモドーロ設定セクションが表示されない。
- 作業完了時に通知ONならローカル通知が送られる。
- 通知OFFならローカル通知が送られない。
- 外部通信と新しい常駐権限を追加しない。
